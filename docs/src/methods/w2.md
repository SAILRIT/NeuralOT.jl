# W₂ Monge maps via ICNNs (Makkuva et al., 2020)

## The formulation

Brenier's theorem says the optimal map for the squared cost is the gradient of a
convex function. Writing the dual in terms of a convex potential and its
conjugate, and parameterising the conjugate's argmax by a second convex
potential, gives the saddle point

```math
\inf_f \sup_g \;
  \mathbb{E}_\mu\!\left[\langle X, \nabla g(X)\rangle - f(\nabla g(X))\right]
  + \mathbb{E}_\nu[f(Y)].
```

At the saddle point `∇g` transports `μ → ν` and `∇f` transports `ν → μ`. Both
potentials are [`ICNN`](@ref)s, so they are convex in their input for *any*
parameter values and their gradients are always valid Brenier maps.

## The analytic gradient

The objective differentiates `∇g` with respect to `g`'s parameters. Computing
`∇g` by automatic differentiation would make this a nested-AD problem —
slow and, with Zygote, fragile. Instead [`input_gradient`](@ref) computes the
ICNN input gradient with an explicit reverse sweep built only from matrix
products and broadcasts:

```math
\nabla_x f = \sum_l W^x_l{}^\top e_l, \qquad
e_{l-1} = \left(\widehat{W}^z_l{}^\top e_l\right) \odot \sigma'(a_{l-1}),
```

with `e_L = 1` for the linear head. Nothing mutates, so the result is
differentiable with respect to the parameters under a *single* level of
reverse-mode AD. This is verified to machine precision against both finite
differences and autodiff in the test suite.

## Strong convexity

`ICNN` includes a learnable term `β/2 ‖x‖²`. With `β = 1` and small input
weights the potential starts close to `‖x‖²/2`, so the map starts close to the
identity. This matters: without it the saddle point is much harder to reach.
Control it with `quadratic` and `init_scale`.

## Example

```julia
using NeuralOT
mu = gaussian_sampler(2; sigma = 0.5)
nu = gaussian_sampler(2; mean = [3.0, 0.0], sigma = 0.5)

res = solve_w2(mu, nu; dim = 2, widths = [64, 64, 1], steps = 2_000,
               inner_steps = 8, lr = 1e-3, seed = 0)

X = mu(1_000)
forward = monge_map(res, X)          # ∇g : μ → ν
back    = inverse_map(res, nu(1_000))  # ∇f : ν → μ
```

## Reading the loss curve

Don't. The objective is a minimax problem and oscillates by construction. Judge
the map with [`sinkhorn_divergence`](@ref) against target samples, or
[`transport_error`](@ref) against a closed-form map when one exists.

## Tuning

| Symptom | Try |
|---|---|
| map barely moves | more `inner_steps`, higher `lr_inner` |
| map overshoots or oscillates | lower `lr`, more `inner_steps` |
| map ignores the target's shape | wider `widths`, longer training |
| the two potentials disagree | non-zero `cycle` regularisation |
